# Eluntra デザインシステム（v7.3.0）

Eluntra 全体（本体チャット＋ Eluntra Developer）のデザイン規則の正。
値の実体は `src/styles/tokens.css` が唯一の定義場所であり、この文書と実装は一致させる。
監査の記録は `~/workspace/eluntra-rebuild/DESIGN-AUDIT-v730.md`。

## ブランドの基準（北極星）

v7.0 のホーム原画がブランドの正：星ロゴ（青→紫グラデーションの四芒星＋軌道リング、`src/components/Logo.tsx`）、
「あなたの想像を、もっと先へ。」のヒーロー、提案カード4枚、ピル型コンポーザー、白基調＋淡いブルーの波。
この骨格とロゴは変更しない。グラデーションはロゴとブランド資産（提案カードの吹き出しアイコン）だけに許し、
本体UIの面・ボタン・背景の装飾には使わない。

## 基本思想

- 画面ごとに「目的／最初に見る情報／次の操作」を決め、不要な要素は追加ではなく削除で解く。
- 形は影ではなく **罫線と濃度** で作る。影は原則なし。
- 状態は色だけに依存しない（太字・罫線・リングを併用する）。
- 参考にするのは Linear / Vercel / Notion 等の情報設計と一貫性であり、見た目のコピーはしない。

## タイポグラフィ

フォントは --font-body / --font-head（丸みのある和文ゴシック系）＋ --font-mono。
スケールはトークンで固定し、場面ごとに勝手なサイズを作らない。

| トークン | サイズ | 用途 |
|---|---|---|
| --text-xs | 11.5px | バッジ等の最小ラベル（多用しない） |
| --text-sm | 12.5px | メタ情報・注記 |
| --text-md | 13.5px | 小ボタン・リストの補助 |
| （既定） | 14〜14.5px | ボタン・リスト本文 |
| --text-base | 15.5px | 本体チャットの本文（行間 --leading-body 1.75） |
| --text-lg | 17px | ヒーローのタグライン等 |
| --text-xl | 20px | ロゴ文字・見出し小 |
| --text-title | 22px | 画面タイトル（Developer ダッシュボード等） |

- **最小サイズ**：補助テキストの下限は 12px（スマホでは 12.5px を目安）。それ未満は装飾ラベルだけに限る。
- 見出しはサイズだけでなくウェイト（700/800）と余白で階層を作る。セクション見出しは 12px・字間 --tracking-label（0.06em）・--text-3。
- 製品名（ヒーロー 58px）はブランド表示として例外。スマホでは 40px に縮小する（後述）。

## 余白とレイアウト

- 余白スケール：--space-1(4) / 2(8) / 3(12) / 4(16) / 5(20) / 6(24) / 8(32)。関連する要素は近く、無関係な要素は離す。
- チャットの読み幅は 780px（コード時は 1080px）で固定し、画面いっぱいに広げない。
- カードは実体のある単位（提案・プロジェクト・変更履歴）だけ。全要素のカード化はしない。

## 半径

--radius-xs(8) / sm(12) / md(16) / lg(22) / pill(999)。
部品固有の例外：ユーザーバブル 20px、コンポーザー 30px、モバイルのシート上部 24px。これ以外の直書きはしない。

## 影

原則なし（--shadow-card: none）。例外は2つだけ：
- コンポーザー：--shadow-composer（0 1px 2px、ほぼ無彩色）で地から僅かに分離する。
- 浮く面（シート／確認ダイアログ／トースト／モバイルのドロワー）：--sheet-shadow。
青みを帯びた影・光るボーダーは禁止。

## アイコン

線描きSVGのみ（絵文字禁止）。サイズは 22px（--icon）と 16px（--icon-sm）に統一、線幅 1.8。
プロバイダー／コネクタの公式ロゴは画像のまま使う（文字タイルはロゴが無い場合の代替）。

## コンポーネント規則

### ボタン（4階層、本体・Developer 共通）
| 階層 | 見た目 | 用途 |
|---|---|---|
| Primary（.btn.primary） | --accent 塗り＋白文字 | 画面の主要操作（1画面に原則1つ） |
| Secondary（.btn / .btn.secondary） | 表面色＋--line-strong 罫線 | 通常の操作 |
| Ghost（.btn.ghost / .iconbtn） | 背景なし | ツールバー・補助操作 |
| Destructive（.btn.danger） | 表面色＋ --error の罫線と文字 | 削除等。塗りつぶし赤は使わない（確認ダイアログ内でも同じ） |

- 高さ：既定 --control-h(44px)、小 --control-h-sm(36px)、極小 --control-h-xs(32px)。形はピル。
- 状態：hover（地色を --bg-sub へ／primary は brightness 0.94）、active（--accent-soft）、disabled（opacity .45＋カーソル既定）、focus-visible（2px の --accent アウトライン＋offset 2px）。
- Developer は密度の都合で既定が --control-h-sm だが、階層・状態の規則は本体と同一。

### 入力
- 枠は --line-strong、半径 --radius-md（Developer の小入力は --radius-sm）、高さ --input-h(44px) 以上。
- focus：枠を --accent にし、--focus-ring（accent-soft の 3px リング）を付ける。本体・Developer 共通（v7.3.0 で Developer に新設）。
- disabled：opacity .5＋地を --bg-sub。
- **スマホ（≤1023px の Developer／≤760px の本体）では全入力 16px・高さ44px 以上**（iOS の入力時自動ズーム防止。maximum-scale 等は使わない）。この規則は絶対に回帰させない。

### カード／リスト／シート
- カード：--surface＋--line の罫線＋--radius-lg。影なし。選択中は罫線を --accent に変えるか、背景 --accent-soft＋内側リング＋太字で示す（色だけに頼らない）。
- リスト行：hover で --bg-sub、選択中は上記に加えて太字。区切りは --line。
- シート／モーダル：暗幕は --scrim。スマホは下部シート（上部半径 24px）、PC は中央。開閉は 160–180ms のフェード＋僅かな移動のみ。
- バッジ：ピル型、11.5px 以上。状態色はトークンの state 色を使う。
- 空状態：目的を1文で示し、次の操作を1つだけ置く。読み込み中は処理中表示（経過秒つき）かスピナー、エラーは日本語＋対処法。

## モーション

--motion-fast(120ms) を部品の状態変化、--motion(180ms) をシート等の面の遷移に使う。
アニメーションは操作結果を分かりやすくするためだけに使い、装飾的な動きは追加しない。
prefers-reduced-motion では遷移とパルスを止める。

## レスポンシブ

- Desktop を縮小するのではなく、各幅で情報構造を組み替える。
- 本体：サイドバーは ≤760px でドロワー化（暗幕 --scrim、開閉はハンバーガー）。現在地は選択中項目の太字＋罫線で示す。
- 本体ヒーロー（スマホ）：ロゴ 104px、製品名 40px、余白を詰め、**最初の画面で提案カードとコンポーザーが同時に見える**ことを基準にする。提案カードは2列のまま文字 13.5px・高さ 62px 以上。コンポーザー下のピルは横スクロールで破綻させない。
- Developer：≤1023px で下部タブの1画面表示（既存方式を維持）。タブのラベルは 11.5px 以上、タップ領域 44px 以上。
- 390px で横はみ出しゼロを実測で確認すること（スクリーンショット検証の必須項目）。

## 禁止事項（AI生成サイト感の排除）

- 意味のないグラデーション／紫＋青のテンプレート配色（ロゴ等のブランド資産を除く）
- 巨大な装飾 Hero（ブランド表示としての製品名は除く）、カードの乱立、全要素のカード化
- 過剰な影・ガラスモーフィズム・光るボーダー・意味のない光のにじみ
- ボタンの乱立、均等割りだけのグリッド、意味のない余白
- 新しい色・サイズ・半径のアドホック追加（要る場合はトークン化してから使う）

## 変更時の手順

1. この文書と監査メモで目的と削除対象を決める → 2. tokens.css に値を置く → 3. 部品・画面へ適用 →
4. ビルド＋テスト → 5. Desktop と 390px のスクリーンショットでチェックリスト（AI生成感／余白／優先順位／見出しの強さ／ボタンとカードの数／色数／コントラスト／モバイル操作性／重要操作の発見性／装飾／一貫性／独自性／商用プロダクト感）を確認し、問題はその場で直す。

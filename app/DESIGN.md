# Eluntra デザインシステム（v8.0.0）

Eluntra 全体（本体チャット＋ Playgrounds）のデザイン規則の正。
値の実体は `src/styles/tokens.css` が唯一の定義場所であり、この文書と実装は一致させる。
監査の記録は `~/workspace/eluntra-rebuild/DESIGN-AUDIT-v730.md`。

## v8.0.0 のデザイン言語（現行の正）

- **シンプル最優先**：ヒーロー（中央ロゴ・大見出し・タグライン・波の装飾）とコードモードは廃止し、本体はチャット一本化した。
  空のチャット画面は「浮いたコンポーザー＋その上の提案チップ列」だけの最小構成にする。
- **星ロゴはアプリ内UIから外した**：サイドバーとログイン画面は「Eluntra」の文字だけの最小表示。
  星ロゴは OG画像とアプリアイコン等のブランド資産としてのみ残る（アプリ内UIには持ち込まない）。
- **浮く透明感**：白基調の上に、半透明＋backdropぼかしのフローティング要素（上部バーの丸ボタンとモデルピル、
  コンポーザーカード、提案チップ、シート、ドロワー）で構成する。トークンは --glass-* と --shadow-float。
  **線引き：透明感はフローティング要素だけに使う。全面ガラス化はしない**（本文の地・リスト・設定項目は不透明のまま）。
  不透明度は、文字の下地として実効コントラストが AA を割らない値に固定する（--glass-bg-strong はシート等の文字が多い面用）。
- **Playgrounds**：旧 Developer。表示名は Playgrounds に統一し、モード名は平易な日本語（相談／作成／デバッグ／レビュー／質問／おまかせ）。
  入口は playgrounds.html（旧 developer.html は転送スタブ）。IDE の密度は保ち、ヘッダーとシートだけ浮く質感に寄せる。

## 基本思想

- 画面ごとに「目的／最初に見る情報／次の操作」を決め、不要な要素は追加ではなく削除で解く。
- 形は原則 **罫線と濃度** で作る。影はフローティング要素の分離（--shadow-float / --sheet-shadow）だけに使う。
- 状態は色だけに依存しない（太字・罫線・リングを併用する）。
- 参考にするのは Linear / Vercel / Notion 等の情報設計と一貫性であり、見た目のコピーはしない。

## タイポグラフィ

フォントは --font-body / --font-head（丸みのある和文ゴシック系）＋ --font-mono。
スケールはトークンで固定し、場面ごとに勝手なサイズを作らない。

| トークン | サイズ | 用途 |
|---|---|---|
| --text-xs | 11.5px | バッジ等の最小ラベル（多用しない） |
| --text-sm | 12.5px | メタ情報・注記 |
| --text-md | 13.5px | 小ボタン・リストの補助 |
| （既定） | 14〜14.5px | ボタン・リスト本文 |
| --text-base | 15.5px | 本体チャットの本文（行間 --leading-body 1.75） |
| --text-lg | 17px | 画面見出し等 |
| --text-xl | 20px | ブランド文字・見出し小 |
| --text-title | 22px | 画面タイトル（Playgrounds ダッシュボード等） |

- **最小サイズ**：補助テキストの下限は 12px（スマホでは 12.5px を目安）。それ未満は装飾ラベルだけに限る。
- 見出しはサイズだけでなくウェイト（700/800）と余白で階層を作る。セクション見出しは 12px・字間 --tracking-label（0.06em）・--text-3。
- 巨大な製品名の見出しは置かない（v8.0.0 でヒーローを廃止）。

## 余白とレイアウト

- 余白スケール：--space-1(4) / 2(8) / 3(12) / 4(16) / 5(20) / 6(24) / 8(32)。関連する要素は近く、無関係な要素は離す。
- チャットの読み幅は 780px で固定し、画面いっぱいに広げない。
- カードは実体のある単位（プロジェクト・変更履歴）だけ。提案や設定項目のような「並び」は罫線の行/リストで表す。全要素のカード化はしない。

## 半径

--radius-xs(8) / sm(12) / md(16) / lg(22) / pill(999)。
部品固有の例外：ユーザーバブル 20px、コンポーザーカード 28px、モバイルのシート 24px（全周）。これ以外の直書きはしない。

## 影

カード類は原則なし（--shadow-card: none）。影を使うのは浮く面だけ：
- フローティング要素（上部バーの部品／コンポーザーカード／提案チップ）：--shadow-float。
- シート／確認ダイアログ／トースト／モバイルのドロワー：--sheet-shadow。
青みを帯びた影・光るボーダーは禁止。影は「浮いていること」を伝える最小限に留める。

## アイコン

線描きSVGのみ（絵文字禁止）。サイズは 22px（--icon）と 16px（--icon-sm）に統一、線幅 1.8。
プロバイダー／コネクタの公式ロゴは画像のまま使う（文字タイルはロゴが無い場合の代替）。

## コンポーネント規則

### ボタン（4階層、本体・Playgrounds 共通）
| 階層 | 見た目 | 用途 |
|---|---|---|
| Primary（.btn.primary） | --accent 塗り＋白文字 | 画面の主要操作（1画面に原則1つ） |
| Secondary（.btn / .btn.secondary） | 表面色＋--line-strong 罫線 | 通常の操作 |
| Ghost（.btn.ghost / .iconbtn） | 背景なし | ツールバー・補助操作 |
| Destructive（.btn.danger） | 表面色＋ --error の罫線と文字 | 削除等。塗りつぶし赤は使わない（確認ダイアログ内でも同じ） |

- 高さ：既定 --control-h(44px)、小 --control-h-sm(36px)、極小 --control-h-xs(32px)。形はピル。
- 状態：hover（地色を --bg-sub へ／primary は brightness 0.94）、active（--accent-soft）、disabled（opacity .45＋カーソル既定）、focus-visible（2px の --accent アウトライン＋offset 2px）。
- Playgrounds は密度の都合で既定が --control-h-sm だが、階層・状態の規則は本体と同一。

### 入力
- 枠は --line-strong、半径 --radius-md（Playgrounds の小入力は --radius-sm）、高さ --input-h(44px) 以上。
- focus：枠を --accent にし、--focus-ring（accent-soft の 3px リング）を付ける。本体・Playgrounds 共通。
- disabled：opacity .5＋地を --bg-sub。
- **スマホ（≤1023px の Playgrounds／≤760px の本体）では全入力 16px・高さ44px 以上**（iOS の入力時自動ズーム防止。maximum-scale 等は使わない）。この規則は絶対に回帰させない。

### カード／リスト／シート
- カード：--surface＋--line の罫線＋--radius-lg。影なし。選択中は罫線を --accent に変えるか、背景 --accent-soft＋内側リング＋太字で示す（色だけに頼らない）。設定のプロバイダー項目はカードにせず、罫線で区切る行/リストにする（骨格の章を参照）。
- リスト行：hover で --bg-sub、選択中は上記に加えて太字。区切りは --line。
- シート／モーダル：暗幕は --scrim。面は --glass-bg-strong＋ぼかしの浮く質感。スマホは下端から少し浮かせた全周角丸のカード、PC は中央。開閉はモーショントークンのフェード＋滑走のみ。
- バッジ：ピル型、11.5px 以上。状態色はトークンの state 色を使う。
- 空状態：目的を1文で示し、次の操作を1つだけ置く。本体の空チャットは例外的に「何も置かない」（提案チップはコンポーザー側に属する）。読み込み中は処理中表示（経過秒つき）かスピナー、エラーは日本語＋対処法。

## 骨格（v8.0.0：浮く要素で構成する）

- 上部バーは画面端に張り付かせない **浮いた要素の集合**：バー自体は透明で、左=丸ボタン（メニュー）、
  中央=モデル選択ピル、右=丸ボタン群（新規チャット／検索／アカウント）が、それぞれ --glass の面＋--shadow-float で浮く。
  3ゾーン構成（左右は等幅グリッド）でモデル選択を幾何学的な中央に置く点は v7.3.3 から維持する。
- 上部バーにブランド表示は置かない。ブランド表示はサイドバーとログイン画面の「Eluntra」の文字だけ（ロゴマークは置かない）。
- コンポーザーは下端から浮いた **角丸カード**（--glass＋--shadow-float、半径 28px）。中に入力行とピル行を収める。
- 空チャットの提案は、コンポーザーの上に置く **横スクロールの小さなチップ列**（ピル型・浮く面）だけにする。大きな提案行や見出しは置かない。
- サイドバーは淡い面＋右罫線の静かな階層を維持し、モバイルのドロワー時だけ浮く半透明の質感にする。
  Playgrounds は IDE の情報密度が要るため、浮く質感はヘッダーとシートに限定する。

## モーション（v7.3.1 で体系化）

「ぬるっとした動き」をトークンで定義し、場当たりな値を足さない。

### 時間の階層（3段）
| トークン | 値 | 用途 |
|---|---|---|
| --motion-fast | 120ms | 短：hover/active 等の状態変化、押下の反応 |
| --motion | 200ms | 中：要素の登場、暗幕やリストの出現 |
| --motion-slow | 340ms | 長：シート/ドロワー/パネル級の移動、チャット拡大の幅遷移 |

### イージング（CSS変数で定義）
| トークン | 値 | 用途 |
|---|---|---|
| --ease | cubic-bezier(0.33, 1, 0.68, 1) | 標準。状態変化全般の滑らかな減速 |
| --ease-out | cubic-bezier(0.22, 1, 0.36, 1) | 出現。速く出てゆっくり止まる（メッセージ・トースト・パネル） |
| --ease-sheet | cubic-bezier(0.32, 0.72, 0, 1) | 滑走。シートとドロワーのスライド（iOS系シートカーブ） |

### 適用原則
- 動かすのは `transform` と `opacity` だけ（レイアウトプロパティのアニメーションは幅遷移など意図した箇所だけ）。
- 派手なバウンス・オーバーシュートは禁止。動きは操作の結果が伝わるものだけ（開閉、登場、押下、切替）。
- 押下感は scale 0.94〜0.98 の範囲で付ける（ボタン、アイコンボタン、送信、チップ、ピル）。
- 割り込み可能で自然に：遷移は常に現在の見た目から始まる（transition のみで構成し、状態を飛ばさない）。

### 適用箇所
本体：ドロワー開閉（--motion-slow × --ease-sheet）、シート/暗幕（--motion-slow × --ease-sheet ／ --motion）、
モデルリストの展開、末尾メッセージの出現（msg-in）、トーストの出現、提案チップと各ボタンの hover/active。
Playgrounds：シート/確認カードの登場、下部パネルの出現、タブとモードの切替、チャット拡大の幅遷移、メッセージのフェード。

### reduced-motion
`prefers-reduced-motion: reduce` では、全要素の transition/animation の duration を 0.01ms まで短くし
（状態の即時反映だけを残す）、処理中パルスとスピナーは静止させる。本体・Playgrounds の両方で必須。

## レスポンシブ

- Desktop を縮小するのではなく、各幅で情報構造を組み替える。
- 本体：サイドバーは ≤760px でドロワー化（暗幕 --scrim、開閉はハンバーガー）。現在地は選択中項目の太字＋罫線で示す。
- 本体の空チャット：中央には何も置かない。提案チップ列とコンポーザーが最初の画面で同時に見えることを基準にする。チップ列は横スクロールで破綻させない。
- Playgrounds：≤1023px で下部タブの1画面表示（既存方式を維持）。タブのラベルは 11.5px 以上、タップ領域 44px 以上。
- 390px で横はみ出しゼロを実測で確認すること（スクリーンショット検証の必須項目）。

## 禁止事項（AI生成サイト感の排除）

- 意味のないグラデーション／紫＋青のテンプレート配色（OG画像等アプリ外のブランド資産を除く）
- 巨大な装飾 Hero（v8.0.0 で全廃。再導入しない）、カードの乱立、全要素のカード化
- 過剰な影・光るボーダー・意味のない光のにじみ。**全面ガラス化**（半透明＋ぼかしはフローティング要素だけ。下記の線引きを守る）
- ボタンの乱立、均等割りだけのグリッド、意味のない余白
- 新しい色・サイズ・半径のアドホック追加（要る場合はトークン化してから使う）

## 変更時の手順

1. この文書と監査メモで目的と削除対象を決める → 2. tokens.css に値を置く → 3. 部品・画面へ適用 →
4. ビルド＋テスト → 5. Desktop と 390px のスクリーンショットでチェックリスト（AI生成感／余白／優先順位／見出しの強さ／ボタンとカードの数／色数／コントラスト／モバイル操作性／重要操作の発見性／装飾／一貫性／独自性／商用プロダクト感）を確認し、問題はその場で直す。
